# Link Shortener - сокращение ссылок со статистикой

REST API-сервис для создания коротких ссылок и просмотра статистики
переходов. Пользователь регистрируется, получает JWT-токен, создаёт
ссылки и управляет ими. При переходе по короткому адресу сервис
перенаправляет посетителя на исходный URL и сохраняет событие перехода.

## Возможности

-   Регистрация пользователей с проверкой пароля и уникальности имени
    пользователя.
-   Аутентификация по JWT: access- и refresh-токены.
-   Получение информации о текущем пользователе.
-   Создание коротких ссылок с автоматически генерируемым кодом.
-   Просмотр списка и отдельной ссылки, удаление собственных ссылок.
-   Проверка URL: разрешены только схемы `http` и `https`.
-   Публичный редирект на исходный адрес.
-   Отключение ссылки с ответом `410 Gone`.
-   Подсчёт переходов и сохранение истории событий.
-   Статистика переходов за период с разбивкой по дням.
-   Получение пяти наиболее популярных ссылок текущего пользователя.
-   Пагинация истории переходов.

## Установка и запуск

### 1. Клонирование проекта

``` bash
git clone <URL-репозитория>
cd link-shortener-main
```

Если проект уже скачан архивом, распакуйте его и перейдите в каталог,
где находится `manage.py`.

### 2. Создание виртуального окружения

Windows PowerShell:

``` powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Если PowerShell запрещает запуск скрипта активации, можно использовать
Command Prompt:

``` bat
.venv\Scripts\activate.bat
```

Linux / macOS:

``` bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установка зависимостей

``` bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Создание базы данных PostgreSQL

Создайте пользователя и базу данных. Например, в `psql`:

``` sql
CREATE USER link_user WITH PASSWORD 'your_password';
CREATE DATABASE link_shortener OWNER link_user;
```

### 5. Настройка переменных окружения

Создайте в корне проекта файл `.env` на основе `.env.example`:

``` dotenv
DB_NAME=link_shortener
DB_USER=link_user
DB_PASSWORD=your_password
DB_HOST=127.0.0.1
DB_PORT=5432
```

### 6. Применение миграций

``` bash
python manage.py migrate
```

### 7. Запуск сервера

``` bash
python manage.py runserver
```

По умолчанию локальный сервер Django доступен по адресу
`http://127.0.0.1:8000`.

> В текущей конфигурации `SHORT_URL_BASE` задан как
> `http://127.0.0.1:8000`. Для другого домена или порта измените это
> значение в `config/settings.py`.

## API

Все API-маршруты используют префикс `/api/`. За исключением регистрации,
получения JWT и публичного редиректа, API требует JWT-аутентификацию.

Для защищённых запросов передавайте заголовок:

``` http
Authorization: Bearer <access_token>
```

### Аутентификация и пользователи

| Метод | Endpoint | Описание | Доступ |
|:---:|---|---|---|
| `POST` | `/api/auth/register/` | Регистрация пользователя | Публичный |
| `POST` | `/api/auth/token/` | Получение access- и refresh-токенов | Публичный |
| `POST` | `/api/auth/token/refresh/` | Обновление access-токена | По refresh-токену |
| `GET` | `/api/auth/me/` | Получение информации о текущем пользователе | JWT |

#### Регистрация

`POST /api/auth/register/`

``` json
{
  "username": "example_user",
  "email": "user@example.com",
  "password": "Use-a-strong-password-123!"
}
```

Пароль проходит встроенные валидаторы Django. При успешной регистрации
возвращается `201 Created`.

#### Получение токенов

`POST /api/auth/token/`

``` json
{
  "username": "example_user",
  "password": "Use-a-strong-password-123!"
}
```

В ответе возвращаются `access` и `refresh`.  
Время жизни access-токена - 15 минут, refresh-токена - 7 дней.

#### Обновление токена

`POST /api/auth/token/refresh/`

``` json
{
  "refresh": "<refresh_token>"
}
```

#### Текущий пользователь

`GET /api/auth/me/`

Возвращает `id`, `username` и `email` пользователя, определённого по
JWT.

### Управление ссылками

| Метод | Endpoint | Описание | Доступ |
|:---:|---|---|---|
| `POST` | `/api/links/` | Создать короткую ссылку | JWT |
| `GET` | `/api/links/` | Список собственных ссылок | JWT |
| `GET` | `/api/links/{id}/` | Получить собственную ссылку | JWT |
| `DELETE` | `/api/links/{id}/` | Удалить собственную ссылку | JWT |
| `GET` | `/api/links/top/` | Топ-5 собственных ссылок по количеству переходов | JWT |

#### Создание ссылки

`POST /api/links/`

``` json
{
  "original_url": "https://example.com/articles/python"
}
```

Короткий код генерируется сервером. В ответе содержатся идентификатор,
исходный URL, код, короткий URL, число переходов и дата создания.
Владелец определяется по текущему JWT-пользователю.

При проверке URL разрешены только схемы `http` и `https`; URL должен
содержать доменное имя и не превышать 2048 символов.

#### Пример ответа

``` json
{
  "id": 1,
  "original_url": "https://example.com/articles/python",
  "short_code": "Ab3xK9q",
  "short_url": "http://127.0.0.1:8000/Ab3xK9q",
  "clicks_count": 0,
  "created_at": "2026-09-28T12:00:00Z"
}
```

#### Топ-5 ссылок

`GET /api/links/top/`

Возвращает до пяти ссылок текущего пользователя, отсортированных по
`clicks_count` по убыванию. При одинаковом количестве переходов
используется сортировка по `id`.

### Переход по короткой ссылке

``` http
GET /<short_code>
```

Например:

``` text
GET http://127.0.0.1:8000/Ab3xK9q
```

Для активной ссылки сервис создаёт запись о переходе, атомарно
увеличивает счётчик и отвечает редиректом `302` на исходный URL.

-   Неизвестный код: `404 Not Found`.
-   Отключённая ссылка: `410 Gone`.
-   JWT для перехода не требуется.

Каждый успешный запрос к активной короткой ссылке учитывается как
переход. Это количество запросов, а не число уникальных пользователей.

### Статистика и история переходов

| Метод | Endpoint | Описание | Доступ |
|:---:|---|---|:---:|
| `GET` | `/api/links/{id}/stats/?from=YYYY-MM-DD&to=YYYY-MM-DD` | Статистика за период с разбивкой по дням | JWT |
| `GET` | `/api/links/{id}/clicks/` | История переходов по ссылке | JWT |

#### Статистика за период

Пример:

``` http
GET /api/links/1/stats/?from=2026-09-01&to=2026-09-28
```

Параметры `from` и `to` обязательны и должны иметь формат `YYYY-MM-DD`.
Начальная и конечная даты включаются в период. Если даты указаны в
неверном формате или `from` позже `to`, API возвращает ошибку валидации.

Ответ содержит данные ссылки, общее число переходов за период и
`daily_stats` - количество переходов по дням.

#### История переходов

`GET /api/links/1/clicks/`

История отсортирована от новых событий к старым. Размер страницы - 50
записей. Событие содержит идентификатор и время перехода.

Доступ к статистике доступен только для авторазированного пользователя и только для этого аккаунта.

## Модели данных

### Link

Хранит короткую ссылку:

-   `owner` - владелец;
-   `original_url` - исходный URL;
-   `short_code` - уникальный короткий код;
-   `clicks_count` - число переходов;
-   `is_active` - активность ссылки;
-   `created_at` - дата создания.

Короткий код генерируется из латинских букв и цифр с помощью `secrets`.
Уникальность обеспечивается ограничением базы данных.

### Click

Хранит событие перехода:

-   `link` - ссылка, по которой перешли;
-   `clicked_at` - дата и время события.

События и счётчик обновляются в транзакции. Счётчик увеличивается
атомарно с помощью `F()`.
